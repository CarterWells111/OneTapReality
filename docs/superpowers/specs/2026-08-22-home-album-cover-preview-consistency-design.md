# 主页旅行册封面预览一致性设计

## 背景

页面预览已经使用 `CanvasPage` 按缩略图宽度渲染真实页面布局，并通过内容缩放比例同步缩小文字字号、行高和内边距。主页“我的旅行册”封面也使用 `CanvasPage` 渲染第一页，但没有传入相同的内容缩放比例，因此图片布局基本一致，文字却可能出现字号偏大、换行不同或被截断。

## 目标

- 主页封面完整等比例缩小旅行册第一页。
- 文字、图片、背景、换行和裁切效果与实际第一页一致。
- 保留主页现有两列布局、封面尺寸、圆角、多选和点击行为。
- 页面预览和主页封面复用同一套缩放计算，避免以后再次分叉。

## 非目标

- 不改变旅行册页面数据或保存格式。
- 不生成、保存或缓存封面截图。
- 不改变页面编辑器、阅读器、页面预览的布局或交互。
- 不改变旧相册兼容布局的内容。

## 设计

### 统一缩放关系

提取一个无副作用的共享方法，根据展示宽度和标准编辑画布宽度计算内容缩放比例。标准编辑画布宽度继续遵循页面预览当前使用的窗口宽度约束，确保已有页面预览视觉不变。

页面预览和主页 `MemoryBookCover` 都调用该方法，并将结果作为 `contentScale` 传给 `CanvasPage`。`CanvasPage` 继续负责把比例传到 `CanvasElement`，由现有文字渲染逻辑同步缩放字号、行高、内边距和文字框圆角。图片和其他元素仍按画布宽高与归一化布局计算，无需额外缩放分支。

### 主页封面渲染

主页继续读取 `memory.pages[0]`。第一页有新版 `layout` 时直接使用；旧相册缺少 `layout` 时继续调用 `createLegacyLayout`。封面实际宽度由现有 `onLayout` 获取，高度保持 3:4。宽度变化后重新计算共享内容缩放比例并重新渲染，但不改变封面外层的两列占比、圆角、按压反馈或多选标记。

### 异常与兼容

共享方法只接受有限且大于零的宽度；无效输入回退为 `1`，与 `CanvasPage` 当前防御逻辑一致。没有第一页的旅行册继续显示现有空封面。缺失本地图片仍由 `CanvasPage` 的现有占位逻辑处理。

## 测试策略

遵循测试先行：

1. 为共享方法写失败测试，验证标准宽度、较小展示宽度和无效输入。
2. 扩展 `MemoryBookCover` 测试，先证明主页封面未把正确的 `contentScale` 传给 `CanvasPage`。
3. 实现共享方法并让页面预览与主页封面共同使用。
4. 运行相关测试，再运行 `npm run lint`、`npm run typecheck`、`npm run test:ci`；因涉及 Expo 页面渲染，再运行 `npm run build:server`。

## 验收标准

- 同一旅行册第一页在实际页面、页面预览和主页封面中保持相同的内容比例。
- 主页封面的文字字号、换行和截断不再偏离实际第一页。
- 主页两列布局、圆角、打开相册和多选行为保持不变。
- 旧相册、空相册和缺失图片的现有回退行为不退化。
