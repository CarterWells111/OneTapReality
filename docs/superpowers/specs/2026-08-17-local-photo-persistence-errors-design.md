# 本地相册照片即时持久化与失败弹窗设计

## 目标

用户在本地相册编辑器中选择普通照片或封面图片后，应用必须先把文件复制到当前账号与相册专属的 `Documents/photos/accounts/<account>/<memory>/` 目录。只有复制成功的 URI 才能进入 Canvas 页面状态，避免 ImagePicker 临时文件被系统清理后出现照片过期。

## 方案选择

采用“选择时严格复制”方案，而不是继续等到整册保存时 best-effort 迁移：

- 选择时严格复制可以在临时文件仍可访问时立即完成持久化，并且失败可以关联到用户刚执行的操作。
- 保存时再复制仍存在选择与保存之间的失效窗口，也会让一次失败影响整册保存。
- 自建 PhotoKit 书签或完整相册选择器超出本次范围，且不能消除应用沙盒被卸载清理的边界。

## 数据流

1. 本地相册或草稿页面向共享 `BookCanvasEditor` 注入账号绑定的照片持久化回调。
2. 用户从系统照片选择器选择照片或封面。
3. 编辑器调用回调，将临时 URI 复制到当前账号、当前相册目录。
4. 复制成功后，Canvas 只接收返回的永久 URI。
5. 复制失败时抛出明确错误，编辑器显示原生弹窗；页面元素、封面和撤销历史保持不变。
6. 整册保存时保留现有 `ensureMemoryPhotosPersisted`，用于旧数据迁移与防御性兜底，但新选择的本地照片不再依赖其 best-effort 行为。

共享礼品编辑器不绑定接收方的本地相册目录，继续使用现有的临时读取、私有 R2 上传和发布流程，不调用本地账号持久化回调。

## 错误处理

弹窗标题为“照片保存失败”，正文提示用户确认照片已从 iCloud 下载，并检查照片权限和设备存储空间后重试。失败的临时 URI 不得写入页面、SQLite 或撤销历史。

应用卸载、系统删除应用沙盒、换设备或 Bundle ID 变化仍不在本地数据保留保证范围内。

## 测试

- 普通照片复制成功后，Canvas 使用账号/相册目录下的永久 URI。
- 封面复制成功后，页面顶层与 layout 使用同一个永久 URI。
- 普通照片复制失败时显示弹窗且不增加元素。
- 封面复制失败时显示弹窗且不修改现有封面。
- 草稿与已保存相册都传入账号绑定的严格持久化回调。
- 共享相册编辑流程保持原有上传行为。

最终运行聚焦测试、`npm run lint`、`npm run typecheck` 和 `npm run test:ci`；按用户要求不运行构建、不提交、不推送、不修改远端。
