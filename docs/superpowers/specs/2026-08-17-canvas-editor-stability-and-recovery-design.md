# 画布编辑稳定性与崩溃恢复设计

## 目标

修复已保存相册编辑时的三个关联问题：调整字号、颜色等属性时画布元素闪烁；iOS 原生进程异常退出后未保存编辑全部丢失；显式保存后只读预览中的文字、图标等元素偶发位置或排版变化。首次生成后的确认草稿页继续使用现有自动保存队列，但复用相同画布交互与渲染修复。

## 当前根因

- 色盘和字号滑杆在手势移动期间持续通过 `runOnJS` 把每一帧写回完整 `StoryPage[]`。这会高频重建 React 状态、画布属性、工具栏和字体解析，是元素边框闪烁及 iOS 原生视图压力的主要来源。
- 已保存相册编辑页仅在用户点击“保存画布”后写入正式相册。进程在此之前退出时，没有可恢复的本地编辑快照。
- 交互态元素与只读元素使用不同的外层定位样式；字体还可能在编辑过程中由回退字体切换为目标字体。编辑与预览因此没有单一、稳定的几何和字体解析结果。

## 状态与数据流

### 高频属性编辑

颜色和字号控件把一次连续拖动视为一个编辑事务：

1. 手势开始时记录元素的已提交值。
2. 手势移动时仅更新控件和元素的 UI 线程临时值，不写回完整页面数组。
3. 手势正常结束或取消时，把最终有效值提交一次给 `BookCanvasEditor`。
4. 数字、十六进制等离散输入仍在值合法并完成编辑时提交；无效中间文本不进入画布数据。

字体选择、预设色、增删元素、层级和背景等离散操作继续单次提交。每个已提交事务只生成一个撤销历史节点。

### 未保存恢复草稿

已保存相册编辑页为当前账号和相册维护一个设备本地恢复草稿。草稿与正式相册分离，不改变用户点击“保存画布”才覆盖正式相册的语义。

- 每次稳定提交后把最新页面快照加入串行合并队列；同一时刻最多执行一次写入，等待中的旧快照由最新快照替代。
- 恢复草稿包含相册 ID、账号隔离键、基础正式相册更新时间、页面数据和草稿更新时间，不包含远程请求或新增第三方服务。
- 重新进入编辑页时，如果草稿对应当前账号和相册且基础版本仍匹配，则直接恢复并显示“已恢复上次未保存的编辑”。
- 正式相册已在别处更新、草稿损坏或 schema 不合法时，不自动覆盖新内容；丢弃不兼容草稿并从正式相册打开。
- 显式保存必须先等待当前变换结束及草稿队列空闲，再写正式相册。保存成功并完成导航前清除恢复草稿；保存失败则保留草稿并停留在编辑页。
- 用户未做更改时不创建草稿。照片仍遵循现有永久本地 URI 规则。

## 统一渲染

`CanvasElement` 提供一套由标准化画布坐标计算出的基础几何样式，交互态和只读态都使用相同的 `left`、`top`、`width`、`height`、`rotation` 与 `zIndex` 规则。交互态只额外叠加手势中的临时偏移、缩放和选择装饰，提交后回到同一基础结果。

文字元素在进入可见画布前解析确定字体。未加载字体使用稳定的本地回退字体；目标字体加载完成后允许字体外观更新，但元素外框坐标不变。编辑页、详情预览和首次生成确认页均通过同一 `CanvasPage`/`CanvasElement` 路径渲染。

## 错误处理与诊断

- 恢复草稿写入失败时不阻塞继续编辑，但显示持久化失败状态，显式保存仍可重试正式写入。
- 正式保存失败不导航、不清草稿，并保留当前页面位置。
- 高频控件只向画布提交有限且合法的数值，避免 `NaN`、空颜色或越界字号进入 Reanimated/native 样式。
- 在开发和 staging 构建中为属性编辑事务、草稿恢复/丢弃及保存边界记录不含用户文本、照片 URI 或秘密的本地诊断事件，便于与 iOS 崩溃日志对照。生产不新增分析或远程日志服务。

## 测试

- 色盘或字号连续产生多次移动事件时，画布只在手势结束提交一次最终值。
- 连续编辑不会卸载或重新挂载当前 `CanvasElement`，选择框保持稳定。
- 属性提交、文字编辑和元素变换会更新恢复草稿；队列合并并串行写入最新快照。
- 模拟页面卸载或进程重开后可恢复匹配版本的未保存草稿；账号或基础版本不匹配时不恢复。
- 正式保存等待变换和草稿写入，成功后清除草稿；失败时草稿仍可恢复。
- 同一元素在交互与只读模式下得到完全一致的基础几何、旋转和层级样式。
- 字体从回退状态变为已加载状态时，元素标准化位置和外框尺寸不改变。
- 首次生成确认页的自动保存行为保持通过，已保存相册仍需显式保存才修改正式相册。

## 范围边界

本次不新增云同步、支付、分析、远程崩溃采集或第三方服务；不改变账号、礼品共享、NFC、staging 隔离和正式相册 schema。恢复草稿只保存在当前设备并按账号隔离。
