# 画布预览、编辑与保存一致性设计

## 目标

修复已保存相册编辑器中的三类一致性问题：页面管理缩略图与打开后的画布排版不同；仍在编辑中的文字、换行、字号、字色和文字框尺寸无法可靠进入正式保存；保存并退出后偶尔返回较早操作的页面。保存操作本身成为明确的提交边界，用户无需先关闭键盘、文字面板或点击“完成”。

## 当前根因

- 页面管理把 `CanvasPage` 直接渲染为较小尺寸。元素的归一化位置和尺寸随画布缩小，但文字的字号、行高、内边距等仍使用原始像素值；缩略图外层边框还会占用并裁切内容区域。因此文字换行、截断和画面边缘与编辑器或详情阅读器不一致。
- 编辑状态分散在三处：父级 `StoryPage[]`、文字/字号/颜色输入框的本地草稿，以及 Reanimated UI 线程上的连续手势预览值。正式保存只读取父级 `pagesRef`，无法保证吸收尚未结束其现有提交回调的最新有效值。
- 当前页游标在 `BookCanvasEditor` 渲染后通过 effect 回传父级。页面管理跳转或翻页后立即保存时，父级 `activePageRef` 可能仍指向上一页。
- 现有聚焦测试分别验证了颜色、字号回调、通用页面持久化和游标回传，但没有覆盖“编辑态仍打开时立即保存”以及“页面切换与保存竞争”的组合时序。

## 方案选择

采用“统一缩放规则 + 编辑器保存事务快照”。不把连续颜色或尺寸预览逐帧写入完整页面数组，避免重新引入高频 React 重渲染、恢复草稿写入和 iOS 原生视图压力；也不把仓库或路由职责移入通用画布编辑器。

`BookCanvasEditor` 保持通用受控组件，但提供一个窄范围保存准备接口。相册编辑路由通过该接口取得已经完成提交的页面快照和当前游标，再执行现有恢复队列、正式仓库写入与导航流程。

## 统一预览渲染

- `CanvasPage`/`CanvasElement` 接受明确的内容缩放信息。页面管理使用 `缩略图内容宽度 / 当前设备主画布宽度` 计算比例；主画布仍沿用现有 `280...360` 像素宽度规则。
- 元素位置、宽高和旋转继续使用现有归一化布局；文字字号、行高、水平/垂直内边距及其他会影响换行或裁切的内容度量按同一比例渲染。
- 图片继续使用与主画布相同的 `contentFit` 和元素宽高比，不创建第二套缩略图布局。
- 页面管理的选中/悬停边框改为覆盖层，不占用 `CanvasPage` 的内容盒，也不裁掉画布边缘。
- 编辑器、详情阅读器、页面管理和导出仍复用同一 `CanvasPage`/`CanvasElement` 内容路径；本次只给较小的管理缩略图提供显示比例，不修改持久化坐标或数据库 schema。

## 保存事务与数据流

`BookCanvasEditor` 暴露 `prepareSave()`，返回 `{ pages, cursor }`。调用过程如下：

1. 锁定新的编辑提交，避免准备快照时出现第二个写入源。
2. 收集当前文字输入，包括显式换行；收集字号和颜色面板中最新的合法草稿或 UI 预览终值。
3. 等待正在收尾的文字框或元素变换提交；手势结束后的归一化 `x`、`y`、`width`、`height` 与 `rotation` 必须进入同一快照。
4. 把全部待提交字段一次性合并到编辑器最新页面引用；新建文字只要发生文字、样式或几何修改，就视为有效元素，不得被“未编辑占位文字”清理逻辑删除。
5. 读取编辑器内部同步维护的 `{ pageId, index }`。页面管理跳转、成功翻页、重排和删除均在状态变化边界立即更新该游标。
6. 返回不可变快照。父级直接使用返回值进行恢复队列等待、正式 `updatePages`、恢复草稿清理以及可选导航，不再重新读取较旧的父级页面或游标引用。

“保存当前修改”和“保存并退出画布”复用同一准备及持久化路径。前者成功后用已保存快照继续编辑并解锁下一次事务；后者把同一快照的游标传给详情页。保存过程中迟到的旧回调继续由现有 session/loadKey/generation 防护拒绝。

## 输入和手势语义

- 多行文字每次 JS 输入变化继续更新受控文本；保存准备会取最终完整字符串，不依赖键盘先失焦。
- 字号数字输入和颜色 RGB/HEX 输入可以保留本地草稿体验，但必须向保存准备接口提供最新草稿。完整合法值提交；空值或不完整值回退到最后一个有效值。
- 色盘与字号滑杆继续在 UI 线程预览，并只在事务结束或保存准备时向页面数据提交一次最终值。
- 文字框拖动、角点缩放、捏合和旋转在活动期间仍只更新共享几何；保存只能在其最终提交被确认后取得快照。
- 编辑页滚动容器允许保存按钮在键盘打开时接收点击，避免第一次点击只关闭键盘而不触发保存。

## 错误处理

- `prepareSave()` 以变换 settled 信号为条件等待；活动变换在 1 秒保护时间内仍未结束时，正式写入不开始，编辑页保持当前内容并显示明确的“正在完成编辑，请重试”状态。
- 无效字号、颜色或非有限几何值不得进入页面快照；对应字段回退到最后一个有效提交值，其他合法编辑仍可保存。
- 正式持久化或恢复草稿清理失败继续沿用现有行为：不丢失当前编辑，不错误导航，并允许重试。
- 保存失败不改变当前页游标；再次保存仍以编辑器最新页面和游标为准。
- 不新增网络日志、分析 SDK、远程素材、依赖、客户端秘密或新的第三方服务。

## 测试

- 页面管理缩略图在不同宽度下按比例缩放文字字号、行高和内边距，元素几何、图片裁切方式及页面边缘不被外层选择边框挤压。
- 多行文字、字号、字色和文字框宽高连续修改后，`prepareSave()` 返回包含全部最终值的单一快照。
- 文字输入框、字号面板或颜色面板保持打开时直接保存，正式仓库收到最新合法值；不要求先失焦或关闭面板。
- 颜色或字号连续手势只提交一个最终页面事务，不恢复逐帧写入。
- 文字框变换尚在收尾时保存会等待最终几何；无效或取消的输入不污染快照。
- 新建文字在发生样式或几何修改后不会被占位清理逻辑删除。
- 页面管理跳转或翻页后立即保存并退出，详情路由收到最后操作页面的 ID 和索引。
- 页面重排或删除目标页时游标按稳定页面 ID 更新；目标被删除时只回退到最近有效索引。
- 现有恢复草稿、临时保存、正式保存失败、旧 session 回调隔离和详情页恢复测试保持通过。

## 验收标准

- 页面管理中的每个缩略图与打开后的同页保持相同元素位置、图片裁切、文字样式和换行关系，仅整体等比缩小。
- 任意文字、换行、字号、字色或文字框尺寸修改，在编辑态仍打开时直接保存也不会丢失。
- “保存并退出画布”始终打开最后操作且仍存在的页面。
- `npm run lint`、`npm run typecheck`、`npm run test:ci` 全部通过；本次触及 Expo 路由和保存导航，按项目门槛额外运行 `npm run build:server`。

## 范围边界

本次不改变相册数据结构、恢复草稿隔离、账号、云端礼品共享、NFC、PDF 导出分辨率或 staging 安全规则；不新增支付、分析、网络请求、依赖或第三方服务。
