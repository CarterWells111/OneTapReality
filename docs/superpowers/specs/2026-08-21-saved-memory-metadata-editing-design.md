# 已保存旅行册名称与日期编辑设计

## 目标

在已保存旅行册的画布编辑页面顶部展示名称与旅行日期，并允许用户在同一编辑会话中修改。名称、日期和页面内容必须通过现有两个显式保存按钮一次性写入，避免部分保存或误触即修改正式旅行册。

## 范围

- 仅修改已保存旅行册进入 `/memory/[id]/edit` 后的编辑体验。
- 编辑页顶部显示旅行册名称和“城市 · 日期”，位置在现有操作提示与画布之前。
- 双击名称后原地切换为文字输入框；日期单击后打开与草稿创建、草稿复核页一致的原生日期选择器。
- “保存当前修改”和“保存并退出画布”同时保存名称、日期和稳定页面快照。
- 草稿复核页、相册详情页、礼品共享、NFC、数据库 schema 和网络契约不改变。

## 交互设计

名称默认以只读文本显示，保留当前旅行册标题的视觉层级。350ms 内连续点击两次名称后，同一位置显示带有 `纪念册标题` 无障碍名称的输入框并自动聚焦；失焦或键盘提交只结束输入状态，不写入正式旅行册。名称控件同时提供无障碍 `activate` 动作，让使用辅助功能的用户无需完成物理双击计数即可进入编辑。再次双击可以继续修改。

日期显示在城市名称后方，并带有可点击提示。单击日期打开原生日期选择器：iOS 使用底部浮层和“完成”按钮，日期范围为 2000-01-01 至当天。选择日期只更新当前编辑会话。

两个现有保存按钮维持原行为：

- “保存当前修改”成功后留在编辑页，继续以已保存的名称、日期和页面作为当前会话基线。
- “保存并退出画布”成功后返回旅行册详情，并恢复到保存时的最后页面。
- 用户通过系统返回或其他导航直接退出时，不把名称或日期写入正式旅行册。

## 状态与数据流

编辑页为当前 `loadIdentity` 初始化独立的元数据编辑状态 `{ title, travelDate }`。账号、旅行册 ID 或 saved/draft 身份变化时，从新的 `Memory` 重新初始化，不能继承上一会话的值。

正式保存开始时，先调用 `BookCanvasEditor.prepareSave()` 获取稳定的 `{ pages, cursor }`，再组合不可变的完整快照：

```ts
const snapshot = {
  ...sessionMemory,
  title: editedTitle,
  travelDate: editedTravelDate,
  pages: prepared.pages,
};
```

该快照交给现有 `updatePages(snapshot, prepared.pages)`。仓储层的完整媒体快照更新必须在同一事务中写入 `title`、`travelDate`、`updatedAt`、封面、照片和页面；账号所有权条件继续使用 `id + ownerAccountKey`。

现有恢复草稿仍只负责页面内容，不扩展 schema。名称与日期在正式保存前仅存在于当前编辑组件状态，因此恢复页面草稿不会悄悄修改正式旅行册元数据。

## 校验与错误处理

- 正式保存前对名称执行 `trim()` 非空校验；失败时不调用 `prepareSave` 后的持久化步骤、不清除恢复草稿、不导航，并显示“请输入纪念册标题”。
- 日期只能由受范围限制的日期选择器产生，并以本地年月日格式化为 `YYYY-MM-DD`，解析时不得使用 UTC 字符串构造导致日期偏移。
- 正式保存失败时沿用现有“保存失败，请稍后重试。”提示，保留名称、日期、页面和当前页，允许再次点击保存。
- 保存进行中禁用名称、日期和两个保存按钮，避免快照捕获后继续修改。
- 相册或账号在异步保存期间切换时，沿用现有 generation/loadKey 防护；迟到的保存结果不得更新新会话或导航。

## 测试设计

在 `__tests__/memory-canvas-editor.test.tsx` 使用编辑页集成测试覆盖：

1. 顶部显示当前名称、城市和日期，名称默认不是输入框。
2. 双击名称后出现输入框，修改值但尚未点击保存时不调用 `updatePages`。
3. 选择日期只更新当前会话，点击“保存当前修改”后 `updatePages` 收到包含新名称、新日期和准备后页面的同一快照，并留在编辑页。
4. 点击“保存并退出画布”以同一方式保存元数据并执行既有返回导航。
5. 空白名称阻止两种正式保存，显示校验提示且不调用持久化。
6. 正式保存失败后元数据仍显示修改值，重试可成功。
7. 切换账号或旅行册后重新显示新旅行册的名称和日期，不复用旧值。
8. 直接卸载编辑页不调用正式保存。

在 `__tests__/memory-repository.test.ts` 保留并强化完整快照对 `title`、`travelDate` 的原子持久化、事务回滚和账号所有权覆盖。

## 验收标准

- 已保存旅行册编辑页可按约定修改名称和日期。
- 未点击正式保存按钮时，重新进入仍显示原正式名称和日期。
- 两个保存按钮都不会产生页面与元数据不一致的部分保存。
- 空白名称、保存失败、快速重复保存和会话切换均不会污染正式数据或其他账号数据。
- `npm run lint`、`npm run typecheck`、`npm run test:ci` 和 `npm run build:server` 全部通过。
