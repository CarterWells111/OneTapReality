# 相册详情操作重排与预览内删除设计

## 目标

精简相册详情页的重复操作入口：编辑与分享只保留标题栏图标；页面预览和礼品绑定移动到阅读器下方；整册删除从标题栏移入只读页面预览底部，并继续要求二次确认。

## 详情页布局

- 普通相册标题栏只显示“分享这册旅行记忆”和“编辑旅行册”两个图标按钮，不显示垃圾桶。
- 删除详情页原有的“编辑相册”和“分享相册”文字大按钮。
- 普通相册的 `PageReader` 下方依次显示“页面预览”和“绑定到礼品”。
- 示例相册的 `PageReader` 下方显示“页面预览”和既有“用自己的照片创建”，不显示礼品绑定或删除。
- 页面预览、编辑、分享和礼品绑定的既有行为保持不变，仅调整入口与位置。

## 预览内整册删除

`PageManagerSheet` 的 `preview` 模式增加可选的整册删除操作。普通相册传入删除回调时，在页面网格之后、底部安全区内显示危险色按钮“删除这册旅行记忆”；示例相册及编辑器的 `manage` 模式不传回调，因此不显示该按钮。

删除按钮只负责请求删除，不直接改变页面数据，也不能复用页面管理的多选删除逻辑。点击后由详情页调用现有确认流程：

- 标题：“删除这册旅行记忆？”
- 说明：“会移入回收站，可在回收站里恢复或彻底删除。”
- “取消”：不调用 `discardMemory`，页面预览保持打开。
- “删除”：调用 `discardMemory(memory.id)`；成功后关闭当前详情并 `router.replace("/")`。

在确认弹窗中选择删除之前，不得写数据库、关闭页面预览或导航。

## 组件接口

`PageManagerSheet` 的 preview 分支增加可选 `onDeleteAlbum?: () => void`。该属性只允许用于 `mode="preview"` 的类型分支；管理模式接口不暴露整册删除。组件在 preview 模式且回调存在时渲染底部危险操作区，点击只调用该回调。

详情页只为非示例相册传入 `onDeleteAlbum={confirmDelete}`。已有 `confirmDelete` 继续拥有 `Alert.alert`、回收站写入和成功导航，避免把相册仓储与路由依赖引入通用画布组件。

## 无障碍与视觉

- 标题栏编辑和分享图标保留现有无障碍名称。
- 删除按钮的可见文字及无障碍名称均为“删除这册旅行记忆”。
- 危险操作区与缩略图滚动内容分离，并使用底部安全区，确保长相册仍可到达删除入口。
- 二次确认继续使用原生 `Alert` 的 destructive 按钮样式。

## 数据与安全

该调整不新增持久化字段、网络请求、依赖、分析、支付、第三方服务或客户端秘密。删除仍调用现有本地 `discardMemory`，进入既有回收站生命周期；示例相册不可删除。

## 测试

- `PageManagerSheet`：preview 传删除回调时显示底部危险按钮并只调用回调；未传时不显示；manage 模式不显示整册删除。
- `MemoryDetailScreen`：普通相册标题栏没有垃圾桶；详情页没有编辑/分享文字大按钮；页面预览和礼品绑定位于阅读器之后；示例相册没有礼品或删除入口。
- 删除确认：点击预览底部删除按钮后出现指定 `Alert`；取消不调用 `discardMemory`、不关闭预览、不导航；确认才调用当前相册 ID，完成后返回首页。
- 既有页面选择、重复恢复、相册身份隔离、标题栏编辑/分享和礼品绑定测试继续通过。
