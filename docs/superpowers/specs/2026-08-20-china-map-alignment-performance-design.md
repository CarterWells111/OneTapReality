# 中国地图竖屏对齐与交互性能设计

## 背景与目标

当前 iPhone 竖屏截图暴露出三个相关问题：省界使用竖屏实际视口居中显示，但标签和产品城市圆点仍可能保留设计时的 `300 × 253` 初始尺寸，导致名称整体悬浮在地图上方；全屏自定义头部在安全区 inset 缺失时会与状态栏或灵动岛重叠；工作区为全部 373 个标签逐帧计算碰撞并为每个标签反复创建透明度动画，拖动和缩放出现明显卡顿。

本次修复以结构性对齐、稳定安全区和减少逐帧工作量为目标。概览卡、36 个产品城市的交互、搜索、弹窗、详情跳转和无障碍契约保持不变。

## 数据范围

生成脚本继续使用固定的 `cn-atlas` 2023 离线快照和既有 SHA-256 校验。标签目录只排除区划码不以 `00` 结尾的 32 个省直辖县级市或县；保留直辖市、地级市、自治州、地区、盟、香港、澳门、台湾以及补充的台北标签。预计目录从 373 个标签收敛为 341 个，最终数量由生成测试锁定。

只有现有 36 个产品城市可点击。其他保留标签仍是不可点击、不可进入无障碍焦点的地图背景，不创建城市档案或新路由。

## 单一内容画布

全屏工作区完成布局后，使用实际宽高计算一个与 `chinaMapViewBox` 等比例、在视口中居中的内容框。省界 SVG、南海附图、圆点和名称都以这个内容框的左上角、宽高和归一化坐标作为唯一基准。

内容画布统一应用平移与缩放。圆点、44pt 点击区和文字以各自锚点为中心做反向缩放，从而保持固定屏幕尺寸；其锚点仍随内容画布移动。这样地图和覆盖物不再分别复制一套“适配竖屏留白”的公式，视口旋转、尺寸变化和首次布局也不会产生不同步。

工作区在真实尺寸到达前不显示标签或可点击圆点，避免初始 `300 × 253` 布局短暂出现在左上方。尺寸变化后同步重置内容框、视口边界和候选标签。

## 标签布局与性能

完整的 341 项目录仅用于生成候选，React 树只挂载当前省会集合和最多 24 个非省会候选，目标上限约为 56 个标签。候选仍遵循省会或直辖市、产品城市、其他地级行政区的优先级，以及中央 `72% × 64%` 显示区、4% 透明度过渡、稳定区划码排序和固定屏幕碰撞框。

候选选择在以下稳定边界更新：真实工作区首次布局、平移或捏合结束、双击缩放结束、搜索定位动画结束，以及缩放层级越过迟滞阈值后稳定。手势逐帧只更新内容画布变换、已挂载标签的反向缩放和中央区边缘透明度；不创建 341 项布局数组，不更新 React 状态，也不逐帧调用 `runOnJS`。

标签进入或退出使用一次约 140ms 的透明度动画。已经可见的标签在普通手势帧不重新启动动画。

## iPhone 安全区与页面结构

全屏页改为直接读取 `useSafeAreaInsets()`，将顶部 inset 应用到固定头部容器，不再依赖外层 `SafeAreaView` 隐式合并 padding。iPhone 竖屏中若运行环境错误地返回零 inset，则采用覆盖灵动岛的最小顶部兜底；有效原生 inset 始终优先。

关闭按钮保持 `44 × 44pt`，位于安全区之下并保留水平内边距。标题、搜索栏和地图视口依次占据剩余高度，地图继续 `flex: 1`，底部由系统安全区裁切而不放置操作按钮。

## 测试与验收

- 生成数据测试锁定 32 个县级条目被移除、保留标签数量、六位区划码唯一和 36 个产品城市完整映射。
- 纯布局测试在窄高竖屏、横向视口和尺寸更新前后验证同一归一化坐标在省界、标签和圆点中的屏幕锚点一致。
- 组件测试验证真实布局前不显示覆盖物、真实布局后只挂载候选池、非候选目录不生成动画组件，并验证非产品标签仍不可点击和不可聚焦。
- 全屏路由测试注入零 inset 与正常 inset，验证关闭按钮的顶部位置、44pt 点击区和地图剩余空间。
- 手势测试验证逐帧路径不更新 React 状态、不调用 `runOnJS`，候选只在手势或动画稳定边界更新，缩放焦点、双击和受限惯性不回归。
- 完成后运行 `npm run lint`、`npm run typecheck`、`npm run test:ci` 和 `npm run build:server`，并在 iPhone 竖屏或可用的等效原生环境手工检查对齐、顶部安全区和拖放流畅度。

## 范围边界

本次不新增依赖、网络请求、地图 SDK、定位、分析、支付、第三方服务或客户端秘密。地图仍是随应用打包的离线示意图，生产发布前继续执行既有标准地图审图核验。
