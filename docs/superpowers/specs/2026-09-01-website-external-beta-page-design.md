# 官网外部内测说明页设计

## 目标

基于最新 `origin/main` 更新 OneTapReality 官网，准确反映第一批 iOS 用户外部测试已经开始，并为测试用户提供一页可独立分享的进度、测试说明和微信群入口。

## 范围

- 新增静态 `/beta/` 页面，并在首页主要导航增加“内测说明”入口。
- 页面明确说明第一批 iOS 用户外部测试已经开始。
- 当前进度列出：NFC 功能已经完成验证、第一批 NFC 纪念品已经生产、贴纸/相框/背景素材已经实现、城市打卡与足迹地图已经实现。
- 测试说明引导用户重点体验上述功能，并说明反馈问题时应提供操作步骤、设备与系统版本、App 版本、截图或录屏；提醒用户不要在群内发送登录验证码、访问令牌或其他敏感信息。
- “加入测试群”区域使用用户提供的完整微信群图片，保留图片中的群名和“有效期至 9 月 8 日、入群后更新”说明。
- 首页产品介绍中，移除或改写与已实现的城市打卡/足迹地图、贴纸/相框/背景素材、NFC 纪念品及碰触体验有关的“未来规划”“尚未实现”“仍在探索”标识。
- 购买、订单、配送、支付、个人旅行数据统计、城市花束商品与文旅合作愿景仍属于未开放范围，相关提示必须保留。

## 页面结构

`/beta/` 延续官网现有米纸底色、砖橙强调色、细墨线和卡片式信息层级，不引入新的视觉系统。

1. 页头：品牌返回首页链接，以及首页、技术支持、隐私政策导航。
2. 首屏：外部测试状态、简短说明和“查看测试重点”“加入测试群”页内锚点。
3. 当前进度：四张状态卡，分别介绍 NFC、首批实体纪念品、本地素材编辑和城市打卡地图。
4. 测试说明：测试平台与阶段、建议测试路径、反馈信息清单和安全提醒。
5. 加入测试群：展示完整二维码图片、有效期提示和扫码说明。
6. 页脚：沿用现有版权与支持入口。

移动端采用单列布局，二维码图片限制最大宽度但保留原始纵横比，避免裁切或重新编码影响扫码。所有文案与图片均随官网静态资源本地提供。

## 静态路由与资源

- 页面文件位于 `website/beta/index.html`。
- 微信群图片复制到 `website/assets/beta/`，使用稳定、可读的文件名。
- `website/scripts/build-static-site.ps1` 将 `/beta/` 与二维码资源加入 Worker 静态构建。
- `website/worker/route.mjs` 按现有目录路由规则解析 `/beta` 与 `/beta/`；如现有规则不能自动处理，则只做最小路由扩展。
- 不使用远程 URL、运行时请求、分析脚本、支付能力或新的第三方服务。

## 文案边界

- “NFC 功能已成功”表述为已经完成当前测试范围内的功能验证，不宣称所有设备、标签或正式生产环境均已覆盖。
- “第一批 NFC 纪念品已生产”只说明样品/测试批次已经落地，不增加购买、订单、配送或支付入口。
- 城市地图和贴纸素材按当前 App 已实现能力表述，不扩展为自动定位、图像识别或云端素材服务。
- 外部测试只表述为 iOS 第一批用户测试，不暗示 App Store 正式公开发布。

## 测试策略

严格按测试先行执行：

1. 先扩展 `__tests__/app-store-site.test.mjs`，要求 `/beta/` 页面、首页导航入口、四项进度、完整二维码本地资源和构建映射存在，并确认测试因功能尚未实现而失败。
2. 增加断言，确保购买、订单、配送、支付、个人统计、城市花束商品与合作愿景仍保留未开放边界；同时确保已实现的三类能力不再被标为尚未实现。
3. 写入最小 HTML、CSS、资源与构建代码，使定向测试通过。
4. 运行静态站点相关测试，再运行 `npm run lint`、`npm run typecheck`、`npm run test:ci`。
5. 本次涉及官网静态 Worker 构建但不改变依赖或 Expo 路由；仍运行 `npm run build:server` 作为生产构建检查。

## 不在本次范围

- TestFlight 邀请或测试资格自动发放。
- 账号白名单、后端、数据库、NFC 写卡流程或 App 功能修改。
- 二维码过期后的自动轮换、后台上传或远程配置。
- 商店购买、订单、配送、支付、分析或新的第三方服务。
