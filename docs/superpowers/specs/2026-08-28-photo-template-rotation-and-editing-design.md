# 照片模板旋转与全相册编辑入口设计

## 目标

修复“手账错落”模板照片接近 180° 倒置的问题，并确保新草稿、旧本地相册、保存后再次编辑的本地相册及共享相册更新都能找到并使用同一套照片与模板入口。

## 已确认根因

模板注册表以设计角度记录 `-3`、`3` 等旋转值，模板缩略图也把这些值解释为角度；正式画布和旋转手势则把持久化旋转解释为弧度。`-3 rad` 约等于 `-172°`，因此“手账错落”模板中的照片接近倒置。再次选择零旋转模板时，错误值被覆盖为 `0`，照片看起来恢复正常。

现有画布手势的输入、动画和保存路径已经使用弧度，因此持久化单位继续采用弧度，避免迁移所有用户手动旋转数据。

## 模板旋转模型

- 模板定义保留易读的设计角度，并通过单一转换函数生成弧度槽位。
- `createPhotoTemplateLayout`、`applyPhotoTemplateToPage` 和 `replacePagePhotos` 只向 `CanvasLayout` 写入弧度。
- 模板选择器和草稿分页预览使用相同的弧度槽位，并以 `rad` 渲染，保证缩略图、草稿和正式画布一致。
- 新草稿第一次生成后即显示正确方向，不依赖用户再次套用模板。

## 旧错误数据兼容

页面规范化仅在以下条件全部满足时修复旧旋转值：

1. `photoTemplateId` 是已知模板；
2. 图片数量与模板照片数量相同；
3. 图片的 `x`、`y`、`width`、`height` 与对应模板槽位匹配；
4. 图片旋转等于历史角度值，而不是正确弧度值。

满足条件时，仅把该图片旋转替换为模板槽位弧度。自由排版、模板 ID 已清除、几何被手动修改或旋转不是历史模板值的页面保持原样，避免覆盖用户编辑。

## 统一编辑入口

`BookCanvasEditor` 将现有“照片布局”改为“照片与模板”，并在每一页固定显示：

- 当前页已有照片：打开编辑流程，可重新选择照片并选择匹配数量的模板；1–3 张显示 5 个模板，4–12 张继续自由排版。
- 当前页没有照片：打开同一流程并要求先选择照片；取消时不改变页面。
- 不再以 `currentPage.kind === "photo"` 决定入口是否出现，因此旧版页面类型、封面或尾页也可添加照片和使用模板。

新草稿审核、本地正式相册编辑与共享相册编辑已经复用 `BookCanvasEditor`，因此入口行为在三类页面中一致。相册详情页继续通过右上角“编辑旅行册”进入正式编辑事务，不增加绕过保存边界的快捷写入。

## 保存与错误处理

- 照片继续先暂存，页面变更被父级接受后再提交；取消、页面消失或保存锁拒绝时回滚。
- 本地正式相册仍只在“保存当前修改”或“保存并退出画布”后写入；共享相册仍只在现有发布事务后写入远端。
- 旧数据修复发生在本地布局规范化，不增加 SQLite 字段，不上传新的标记，也不改变账号隔离。
- 用户看不到旋转单位或迁移提示；无法暂存照片时沿用稳定、可操作的中文错误提示。

## 测试设计

- 模板单元测试证明手账模板的持久化旋转是约 `±0.052 rad`，而不是 `±3 rad`。
- 画布布局测试证明历史角度值只在模板几何匹配时修复，手动旋转与自由排版不变。
- 草稿生成测试证明第一次生成的模板页面使用弧度。
- 编辑器交互测试证明无照片、旧页面和普通照片页都显示“照片与模板”，并遵守照片优先流程。
- 本地正式相册与共享相册集成测试证明它们都向 `BookCanvasEditor` 提供照片暂存能力，并能保存模板变化。
- 完成后运行 `npm run lint`、`npm run typecheck`、`npm run test:ci`、`npm run build:server` 和 `npm run beta:preflight:ios`。

## 范围边界

不新增依赖、数据库字段、网络接口、分析、支付、第三方服务或客户端秘密；不改变页面文字、贴纸、相框、背景和照片顺序。
